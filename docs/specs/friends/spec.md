# 친구 추가와 친구 기록 보기

## 문제와 방향

`PRODUCT.md`는 지인끼리 쓰는 앱을 전제로, 친구를 추가하면 친구가 어떤 무게로 얼마나 운동했는지 볼 수 있다고 약속합니다. 계정별 서버 저장(accounts-and-sync)이 끝났으므로, 접근 규칙을 계정 하나에서 친구까지 넓힙니다.

## 결정한 것

- 친구는 요청과 수락으로 맺습니다. 아이디로 요청을 보내고, 상대가 수락해야 서로 기록을 볼 수 있습니다. 상대가 이미 나에게 요청을 보낸 상태라면 내 요청이 곧 수락이 되어 바로 친구가 됩니다.
- 친구의 기록은 읽기 전용으로 전부 보여 줍니다(날짜별 운동, 머신 브랜드와 모델, 세트별 무게와 횟수). 친구의 기록은 고칠 수 없습니다.
- 친구 끊기, 요청 거절, 요청 취소는 관계를 지우는 같은 동작이고 어느 쪽이든 할 수 있습니다. 끊으면 서로의 기록이 바로 보이지 않습니다.
- 새 화면: 하단 탭 "친구"(친구 아이디로 요청 보내기, 받은 요청, 보낸 요청, 친구 목록)와 친구 한 명의 기록 화면(`/friends/[id]`).

## 동작

1. 친구 화면에서 상대의 아이디를 입력하고 요청하면 "요청을 보냈어요"가 보이고 보낸 요청에 나타납니다. 없는 아이디, 자기 자신, 이미 친구, 이미 보낸 요청은 이유를 알려 주는 문장이 나옵니다.
2. 상대의 친구 화면에 받은 요청이 나타나고, 수락하면 두 사람 모두 친구 목록에 서로가 나타납니다. 거절하면 요청이 사라집니다.
3. 친구 목록에서 "기록 보기"를 누르면 그 친구의 기록이 최근 날짜부터 날짜별로 보입니다. 기록이 없으면 안내 문구가 나옵니다. 무게는 내가 고른 단위(kg, lb)로 보입니다.
4. "친구 끊기"는 한 번 더 눌러야 실행됩니다. 끊은 뒤에는 친구 목록에서 사라지고 그 사람의 기록 주소로 들어가도 볼 수 없다는 안내가 나옵니다.
5. 친구가 아닌 사람은 서버가 행을 주지 않아서, 주소를 알아도 기록을 볼 수 없습니다.

## 구현 방식

- 서버: `profiles`(아이디), `friendships`(요청자, 받는 사람, 상태), 친구의 `workouts`를 읽는 정책, 요청을 만드는 `request_friend` 함수를 `supabase/migrations/20261029200000_add_friends.sql`에 둡니다. 요청은 함수로만 만들 수 있고, 수락은 받는 사람만 할 수 있습니다.
- 화면 구성: `features/friends`(관계 조회와 요청), `features/workout-log`(`fetchWorkoutsOf`로 친구 기록 읽기), `screens/friends`가 둘을 조합합니다. 두 feature는 서로를 모릅니다.

## 가정(사용자가 뒤집을 수 있음)

- 아이디는 로그인 이메일 앞부분이고, 이미 가입한 계정은 마이그레이션이 프로필을 채웁니다. 앞으로 가입하는 계정은 트리거가 채웁니다.
- 아이디를 알면 누구나 요청을 보낼 수 있습니다. 목록 검색은 없고, 상대는 요청을 거절할 수 있습니다. 없는 아이디와 있는 아이디가 다른 문구로 보이므로 아이디가 있는지 알아낼 수는 있습니다.
- 친구 사이에는 기록 전체(과거 포함)가 보이고 일부만 숨기는 설정은 없습니다.

## 이번 범위 밖

- 친구 기록의 달력과 차트 보기(지금은 날짜별 목록만), 친구 기록 비교, 알림, 요청 차단과 신고, 친구 수 제한.
- 마이그레이션은 사용자가 Supabase SQL Editor에서 한 번 실행해야 합니다. 실행하기 전에는 친구 화면이 목록을 불러오지 못합니다.

## 수용 기준

1. 요청 보내기, 받은 요청 수락과 거절, 보낸 요청 취소, 친구 끊기가 동작한다.
2. 수락한 친구의 기록은 읽을 수 있고 고칠 수 없다.
3. 친구가 아닌 계정의 기록은 주소를 알아도 읽을 수 없다.
4. 두 계정으로 실제 요청과 수락을 거쳐 서로의 기록이 보이는 것을 확인한다(서버 마이그레이션 실행 뒤).
